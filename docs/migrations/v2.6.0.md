# Upgrading to v2.6.0

`@a-novel-kit/nodelib-browser/telemetry` reports to Grafana Faro instead of Sentry. Faro replaces
Sentry across the stack (a-novel/.github#527), and Sentry no longer receives anything.

## Do I need to act?

**Required** for a platform that builds a `BrowserTelemetry`: its options change, `navigate()` is
gone, and the Sentry peer gives way to Faro's. A platform without browser telemetry changes nothing.

## Report to Faro

Swap the peers:

```bash
pnpm remove @sentry/browser
pnpm add @grafana/faro-web-sdk @grafana/faro-web-tracing
```

Name the collector, the platform and its version. The collector URL comes from the platform's
Frontend Observability app, and is as public as the DSN was:

```diff
-import { PUBLIC_SENTRY_DSN } from "$app/env/public";
+import { PUBLIC_FARO_URL } from "$app/env/public";

-export const telemetry = new BrowserTelemetry({ dsn: PUBLIC_SENTRY_DSN, release: `platform-studio@${version}` });
+export const telemetry = new BrowserTelemetry({ url: PUBLIC_FARO_URL, name: "platform-studio", version });
```

Rename `PUBLIC_SENTRY_DSN` to `PUBLIC_FARO_URL` in `src/env.ts`, the README and the deployment.

## Name views, not spans

Faro names the view after the route on the page load and on every navigation, so `arrive()` alone
covers both. Drop the `beforeNavigate` call:

```diff
-beforeNavigate((navigation) => telemetry.navigate(navigation));
 afterNavigate(() => telemetry.arrive(page.route.id));
```

## Let the browser reach the collector

Faro posts to its collector, which a `connect-src 'self'` policy refuses. Add the stack's collector
origin to the platform's CSP:

```ts
csp: { directives: { "connect-src": ["self", "https://faro-collector-prod-eu-west-2.grafana.net"] } },
```

## Drop the Sentry trace meta

Faro's tracing continues the platform's traces through the requests a page makes, not through the
page render. Remove `<meta name="sentry-trace" content="%trace%" />` from `src/app.html`, and the
server hook's `%trace%` replacement with it.
