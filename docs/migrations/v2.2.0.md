# Upgrading to v2.2.0

`@a-novel-kit/nodelib-server/telemetry` exports spans over OTLP/HTTP to the backend the standard
`OTEL_EXPORTER_OTLP_*` variables name, as golib's OTLP preset does for the Go services. It no longer
exports to Google Cloud, and drops its `google-auth-library` peer.

## Do I need to act?

**Required** for a platform that passes `gcloudProjectId` to `startTelemetry()`: the option is gone,
and TypeScript rejects it. **Recommended** for a platform with a liveness probe, which can stop
tracing it. A platform that only prints spans locally changes nothing else.

## Export over OTLP

Drop `gcloudProjectId` from the `startTelemetry()` call, and `GCLOUD_PROJECT_ID` from `src/env.ts`
when nothing else reads it. Pass the liveness route in `untracedRoutes`:

```diff
-import { GCLOUD_PROJECT_ID, OTEL } from "$app/env/private";
+import { OTEL } from "$app/env/private";

-const telemetry = startTelemetry({ serviceName: "platform-studio", enabled: OTEL, gcloudProjectId: GCLOUD_PROJECT_ID });
+const telemetry = startTelemetry({ serviceName: "platform-studio", enabled: OTEL, untracedRoutes: ["/ping"] });
```

Remove `google-auth-library` from the platform's dependencies unless its own code imports it.

The deployment then sets the variables the Go services read, next to `OTEL=true`:

| Variable                         | Value                                                         |
| -------------------------------- | ------------------------------------------------------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT`    | Base URL of the OTLP/HTTP backend. The SDK adds `/v1/traces`. |
| `OTEL_EXPORTER_OTLP_HEADERS`     | Headers each export sends, such as the backend's key.         |
| `OTEL_EXPORTER_OTLP_COMPRESSION` | `gzip` compresses each export.                                |

Without an endpoint, spans print to standard output, as they did without a project ID.

## Keep every trace

A span under a remote parent that is not sampled is now recorded too, as golib does, so a proxy that
stamps its own sampling decision on each request no longer hides the platform's spans. This needs no
change.
