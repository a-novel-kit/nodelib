# Upgrading to v2.13.0

nodelib takes in the code every service client and every platform copies: a `RestClient` base, the
Svelte helpers, the end-to-end harness and the preset overrides. It also drops the exports no
repository uses.

## Do I need to act?

**Required** only for a project that imports a removed export, which no repository of either
organization does, for a service client built on `RestClient`, which raises its peer on
nodelib-browser to this release, and for a project that relies on a changed default listed below.
**Recommended** for every service JS client and every platform: each section names the local copies
the release replaces.

## Replace the removed exports

These exports had no consumer, and are gone:

| Package             | Removed                                                                                                        | Use instead                                        |
| ------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `browser/utils`     | `Debounce`, `retry`, `RetryParams`, `RetryFailureFn`                                                           | `retryWithBackoff`, or `retryWhile` in a component |
| `browser/http`      | `newHttpError`                                                                                                 | `handleHttpResponse`, which throws the `HttpError` |
| `browser/telemetry` | `readTelemetryChoice`, `saveTelemetryChoice`, `SaveTelemetryChoiceOptions`                                     | `BrowserTelemetry`'s `choice` and `choose`         |
| `i18n`              | `createRequestI18n`, `NamespaceLoader`, `RequestI18nOptions`                                                   | `createStaticI18n` with bundled catalogs           |
| `server`            | `aggregateHealth({ services, timeoutMs })`, `HealthService`, `HealthServiceRegistry`, `AggregateHealthOptions` | `aggregateHealth({ config, fetch })`               |

`pnpm lint:typecheck` names any import left behind.

## Build a service client on `RestClient`

A service's `pkg/js/rest/src/api.ts` extends `RestClient` from `@a-novel-kit/nodelib-browser/http`
and keeps only its `ping` and `health`. The constructor takes the optional `fetcher` every client
now shares, so a platform drops its header-injecting subclass. `fetchVoid` releases the body it
discards.

```diff
-export class ProfileApi {
-  private readonly _baseUrl: string;
-  constructor(baseUrl: string) { … }
-  async fetchVoid(…) { … }
-  async fetch<T>(…) { … }
-  async fetchBlob(…) { … }
+import { type HealthDependency, RestClient } from "@a-novel-kit/nodelib-browser/http";
+
+export class ProfileApi extends RestClient {
   async ping(): Promise<void> { … }
   async health(): Promise<Record<string, HealthDependency>> { … }
 }
```

A request passes `accessToken` and `json` instead of building its headers and body. A request
without a body sends no `Content-Type`:

```diff
 return await api.fetch("/v1/profile", ProfileSchema, {
   method: "PUT",
-  headers: { ...HTTP_HEADERS.JSON, Authorization: `Bearer ${accessToken}` },
-  body: JSON.stringify(request),
+  accessToken,
+  json: request,
 });
```

The client's `pkg/js/rest/package.json` raises its `@a-novel-kit/nodelib-browser` peer from
`^1.3.18 || ^2.0.0` to this release: an older nodelib-browser has no `RestClient`, and the client
would fail at import.

`HTTP_HEADERS` is deprecated, and leaves in a later release once no client uses it. A plain `fetch`,
such as platform-studio's `src/lib/client/projects/api.ts` calling Studio's own routes, sets
`{ "Content-Type": "application/json" }` beside its body instead. The service's
own `HealthDependency` export can re-export the package's. The narrative engine's `stream` sends
through `this.fetchResponse`, and imports `wait` from `@a-novel-kit/nodelib-browser/utils`, which
leaves no abort listener behind.

## Build a service client with `ViteLibrary`

`@a-novel-kit/nodelib-config/vite-library` publishes the library build nodelib's packages use. A
service's `pkg/js/rest/vite.config.ts`, and service-authentication's `pkg/js/rest-test/vite.config.ts`,
shrink to one call, which keeps `dist/src/index.es.js` and every peer subpath external:

```ts
import manifest from "./package.json" with { type: "json" };

import { ViteLibrary } from "@a-novel-kit/nodelib-config/vite-library";

export default ViteLibrary(import.meta.dirname, { src: "src/index.ts" }, manifest);
```

The output is no longer minified, which the consumer's bundler does anyway, and Node's built-in
modules stay external without a hand-written list. The `--outDir` of service-json-keys' `build`
script goes, since the build writes beside its config.

## Import the Svelte helpers from `nodelib-svelte`

An a-novel-kit owner first makes the newly published package public, as nodelib-browser is: GitHub
creates it private, and a platform's CI token cannot read a private package of another
organization. A platform then adds `@a-novel-kit/nodelib-svelte`, deletes
`src/lib/client/retry.svelte.ts` and its test, `src/lib/ui/downtime.svelte.ts`,
`src/lib/client/telemetry-preference.svelte.ts` and `src/lib/ui/telemetry-preference.ts`, and
imports the same names from the new package.
`retryWhile` reports a bounded run's failure to `onError` instead of the platform's telemetry
module:

```diff
-import { retryWhile } from "#lib/client/retry.svelte.js";
+import { retryWhile } from "@a-novel-kit/nodelib-svelte";

 const listRetries = retryWhile(missing, attempt, {
   maxRetries: 3,
+  onError: (error) => telemetry.captureError(error),
 });
```

The package ships its modules with their runes for the application's Svelte compiler, so the
project needs `svelte` 5.57.3 or later, which every platform has. A SvelteKit server build inlines
it, while nodelib-browser stays one external copy shared with the service clients.

Prefer `isHttpError` and `isHttpStatusError` to `instanceof HttpError`: they match an error by its
name, so they keep working should a bundler ever load two copies of nodelib-browser.

## Drop the preset overrides

The presets now hold what every platform overrode the same way:

- **ESLint.** `EslintSvelte` keeps `svelte/no-at-html-tags` an error and forbids `import.meta.env`
  outside a library (`isLib: true`). Delete the override block, and export the factory's result as
  is: `export default EslintSvelte({ … })`. `Eslint` and `EslintSvelte` return `defineConfig`'s
  result, which a spread still accepts. The base preset no longer turns off
  `@typescript-eslint/no-explicit-any` and `@typescript-eslint/ban-ts-comment`. The one `any` in
  either organization, uikit's `packages/uikit/test/I18nFixture.svelte:16`
  (`component: Component<any>`), cannot become `Component<Record<string, unknown>>`: a component's
  props are contravariant, so a typed component no longer fits. Make the fixture generic instead:
  `<script lang="ts" generics="Props extends Record<string, unknown>">`, with
  `component: Component<Props>` and `props: Props`.
- **Vite.** `SvelteKitVite` sets `paths.origin` from `ORIGIN` and `tracing.server`. Delete both from
  `vite.config.ts`, and account's `frame-ancestors`, which was already the default.
- **Vitest.** `SvelteKitVitest` leaves stories, story harnesses, fixtures and
  `src/lib/i18n/storybook.ts` out of coverage, and takes `optimizeDepsInclude`. Replace the
  `mergeConfig` wrapper and the `validation-dependencies` plugin:

  ```ts
  export default SvelteKitVitest({
    rootUrl: import.meta.url,
    vitePlugins: () => [Yaml()],
    optimizeDepsInclude: ["@a-novel/service-authentication-rest", "zod"],
  });
  ```

- **i18next.** `I18next` reads YAML catalogs by default. Delete `catalogFormat: "yaml"`; a JSON
  project now passes `catalogFormat: "json"`.

## Run the downtime servers from the shared harness

`SvelteKitPlaywright` takes `servers`, one server of the build each, and `port` is deprecated.
nodelib-test lists the downtime servers and serves their documents, and draws the service tokens, so
a platform deletes the body of `tests/e2e/downtime.ts` and most of `tests/e2e/service-token.ts`:

```ts
// playwright.config.ts
export default defineConfig({
  ...SvelteKitPlaywright({ servers: downtimeServers(), serverEnvironment: { … }, use: { … } }),
  globalSetup: ["./tests/e2e/setup.ts", "./tests/e2e/service-token.ts", "./tests/e2e/downtime.ts"],
  workers: 1,
});

// tests/e2e/downtime.ts
export default downtimeSetup();

// tests/e2e/service-token.ts
export default serviceTokenSetup([
  { path: serviceTokenPath, subject: platformCaller },
  { path: profileServiceTokenPath, subject: platformCaller, audience: "profile" },
]);
```

A journey imports `downtimeOrigin("started")` and `callerFetch(subject)` from
`@a-novel-kit/nodelib-test/playwright`. `webServer` is now a list, even for one server.

## Read Mailpit through `nodelib-test/mailpit`

`searchMail` and `mailLinks` read the emails a test sends, without a test runner of their own. A
service's integration suite replaces its Mailpit loop with them and polls through `vi.waitFor`.

## Simplify the platform server

- **Runtime config.** `environmentHttpUrl(name, { defaultValue })` and `environmentOptional(name)`
  replace the `DOWNTIME_URL ?? default` and `*_TOKEN_PATH || undefined` workarounds, so `RuntimeConfig`
  becomes `EnvironmentOutput<typeof schema>`. An optional field is a required key typed
  `string | undefined`, so a test fixture of the config sets `serviceTokenPath: undefined`.
- **Health.** Each service's entry in `aggregateHealth`'s `config` takes its own `fetch`. Pass
  `serviceFetch({ serviceTokenPath })` there, and drop the code that maps a probe URL back to a token.
- **Tracing.** `traceResponse` from `@a-novel-kit/nodelib-server/telemetry` replaces the hook's local
  copy.
- **Preferences.** `savePreference(name, value)` replaces a hand-written `document.cookie`, and adds
  `Secure` over HTTPS.
