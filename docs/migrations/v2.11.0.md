# Upgrading to v2.11.0

`@a-novel-kit/nodelib-i18n` now requires i18next 27. Its peer range moves from `^26.7.2` to
`^27.0.0`.

## Do I need to act?

**Required** for a project that installs `@a-novel-kit/nodelib-i18n`: upgrade i18next with this
release. A project without it changes nothing.

## Upgrade i18next

```bash
pnpm add i18next@27
```

`createStaticI18n` and `createRequestI18n` behave as before. Both set `fallbackLng` and
`returnEmptyString: false` themselves, so i18next 27's new defaults for those options change nothing
for them.

## Pass every variable a message needs

i18next 27 type-checks interpolation by default. A `t()` call must pass every `{{variable}}` its
message names, and a call that omits one no longer compiles:

```diff
-t("account.greeting");
+t("account.greeting", { name });
```

Run the project's type check to find these calls. Set `strictInterpolationChecks: false` in
`CustomTypeOptions` to keep the i18next 26 typing.

## Check direct i18next use

Code that creates its own instance with `createInstance()` takes i18next 27's new defaults. Follow
the [i18next migration guide](https://www.i18next.com/misc/migration-guide#v26.x.x-to-v27.0.0) for
that code.
