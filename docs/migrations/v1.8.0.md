# Upgrading to v1.8.0

The SvelteKit preset targets SvelteKit 3, which reads its options from the Vite plugin instead of
`svelte.config.js`.

## Do I need to act?

**Required** for SvelteKit applications that use `@a-novel-kit/nodelib-config/sveltekit`. Other
entry points and packages are unchanged.

## Upgrade to SvelteKit 3

`@a-novel-kit/nodelib-config` now expects `@sveltejs/kit` ^3.0.0 and `@sveltejs/adapter-node`
^6.0.0. Adapter-node 6 only runs on SvelteKit 3, so bump both together, then follow the
[SvelteKit 3 migration guide](https://svelte.dev/docs/kit/migrating-to-sveltekit-3).

## Move SvelteKit options into the Vite configuration

SvelteKit 3 refuses to start while `svelte.config.js` exists, so `SvelteKit()` is removed. Delete
`svelte.config.js` and pass any SvelteKit options as the second argument of `SvelteKitVite`. The
Node adapter remains the default.

```ts
// before: svelte.config.js
export default SvelteKit({ kit: { paths: { base: "/studio" } } });

// after: vite.config.ts
export default SvelteKitVite({ plugins: [Yaml()] }, { paths: { base: "/studio" } });
```

An application whose `svelte.config.js` only called `SvelteKit()` deletes the file and keeps its
`vite.config.ts` as is.
